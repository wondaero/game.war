# 디펜스 게임 시작 안내 (새 프로젝트용)

> 이 폴더(예전 프로젝트 game.war 전체)는 새 디펜스 프로젝트의 참고 자료로 복사된 것이다.
> 새 프로젝트의 Claude 는 이 파일부터 읽고 시작한다.

## 왜 바꾸는지 (가장 중요)
예전 게임(동시 턴 전술 대전)이 재미없던 이유: **30초 시간 압박 + 상대가 어디로 움직일지 추측 + 턴마다 행동 3번을 신경 써야 해서 조급하고 스트레스.**
→ 새 게임은 "추측" 대신 "계획", "시간 압박" 대신 "내 속도"가 핵심.

## 같이 읽을 것 (이 폴더 기준)
- `docs/worklog.md` : 요청·결정 기록. 맨 아래 "2026-11-26" 이 디펜스로 바꾸게 된 논의
- `docs/design.md` : 예전 규칙 (캐릭터·능력치·특수능력·뽑기 결정)
- `docs/spec` : 특수능력 원문 (사용자 작성)
- `CLAUDE.md` : 작업 규칙 (새 프로젝트에 맞게 새로 만들 것)

## 작업 규칙 (그대로 유지)
- 사용자에게 보이는 글은 **항상 한국어**. 코드·명령·파일 경로만 영어
- 요청을 받을 때마다 새 프로젝트의 `docs/worklog.md` 에 기록 (여러 컴퓨터에서 이어서 작업함)
- 커밋·푸시는 사용자가 요청할 때만
- Supabase 비밀 키는 앱·대화·커밋에 절대 넣지 않기

## 정한 방향
- 장르: **턴제 디펜스.** 적이 길을 따라오고, 길 옆 배치 칸에 캐릭을 세워 피해를 줘 막는다
- 적의 다음 움직임은 화면에 미리 보여 줌. **시간 제한 없음**
- 판: **7열 × 10행**, 칸마다 "길" 또는 "배치 칸". 맵은 데이터로 만들어 여러 개를 돌린다
  1. 가로 지그재그: 1·3·5·7·9행 전부 길, 2·6행 오른쪽 끝과 4·8행 왼쪽 끝이 연결 길, 나머지 배치 칸 (길 39칸, 배치 31칸, 꺾임 4곳 → 쉬움)
  2. M자 (위아래 뒤집으면 W자): 1·3·5·7열이 세로 길, 맨 위 2·6열과 맨 아래 4열이 연결 길, 2·4·6열이 배치 칸 (길 43칸, 배치 27칸, 꺾임 3곳, 입구·출구가 같은 쪽 → 어려움)
- 사거리 **1~2칸** (예전 5~10은 디펜스에 너무 김). 배치 줄이 길 두 줄 사이라 사거리 1로도 두 줄을 때림. 꺾이는 곳 옆이 명당
- 캐릭터 체계 유지: 캐릭터 1종 + 그림 8종(성능 무관, 같은 그림 중복 출전 불가), 뽑기로 능력치, 특수능력 20% 확률로 0~1개
- 뽑기 · 합성(캐릭 3명 → 리롤석 1개) · 리롤(리롤석 1개, 능력치 1개 잠금, 그림·특수능력 유지) · 보관함 · 덱 유지
- 특수능력은 대부분 살리되 디펜스에 안 맞는 것(무효·유도탄 등)은 다시 정한다
- 밸런스 목표: 캐릭빨은 있지만 실력(배치)으로 뒤집을 여지. 실력이 같으면 좋은 쪽이 약 67%. **과금빨은 싫음**
- 나중에 대결: 두 사람이 **같은 웨이브를 각자** 막고 결과 비교 (비동기). 지금은 혼자 하는 시험판부터

## 아직 안 정한 것 (시험판 해 보고 정함)
- 적 이동 속도 (턴제에서 한 턴에 몇 칸; 길 39~43칸이라 1칸씩은 너무 김) 또는 천천히 흐르는 실시간 + 일시정지
- 출전 수 (예전 4명은 적을 수 있음 → 6~8명 또는 웨이브마다 추가 배치)
- 맨 아래 줄 처리, 사거리 모양 (마름모 / 사각형)

## 예전 코드에서 가져다 쓸 것
- 뽑기·합성·리롤·저장 서비스: `packages/core`, `packages/v2/src/gacha.ts`
- 특수능력 표·피해 계산: `packages/v2/src/abilities.ts`, `combat.ts` (수정 필요)
- 시드 난수: `packages/engine/src/rng.ts`
- 로비·상점·내 정보 화면, 그림 8종 표시: `apps/mobile/src`
- Supabase 로그인·서버 저장·서버 판정 구조: `supabase/`, `apps/mobile/src/online`
- 가져오지 않음: 동시 턴 대전 엔진(`resolve.ts` 등), 가위바위보 AI(`ai.ts`), 대전 입력·재생 화면, 실시간 대전 중계

## 첫 작업
1. 위 문서들을 읽고, 이해한 내용과 시험판 계획을 짧게 정리해서 사용자에게 보여 준다 (바로 코드부터 쓰지 않기)
2. 사용자가 확인하면 프로젝트 뼈대를 세우고 혼자 하는 시험판을 만든다
   - 맵 2개 (지그재그, M), 웨이브 2~3개
   - 판 크기·사거리·적 속도·출전 수는 설정으로 바꿀 수 있게
   - 사용자가 브라우저에서 바로 해 보고 재미를 판단할 수 있게
